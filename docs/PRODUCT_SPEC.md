# 产品规格

## 1. 产品定义

PKWS 帮助个人把随手记录长期转化为可靠、可追溯、可编辑的知识写作成果。用户负责表达，系统负责可靠保存、找回、关联和提出整理方案；用户始终保有对原文与文章的最终控制权。

### 成功标准

1. 从产生想法到持久化记录的操作足够少，失败有明确反馈且能安全重试。
2. 原始内容无需 PKWS 即可被阅读、搜索、备份和迁移。
3. 数月后能找回某个观点的上下文、来源和变化，而不是只看到无来源摘要。
4. Agent 维护的是少量有价值的长期文章，且不会反复覆盖用户修改或制造近似文件。
5. 每次自动处理可解释、可重跑、可审阅，故障不会污染原始记录。

文件数、标签数、知识对象数和模型调用量都不是成功指标。

## 2. 用户范围与边界

当前面向单个 Windows 用户。P0 自带轻量连续笔记界面，用户文档固定放在程序目录的 `doc` 下；后续 Agent、wiki 和可选外部编辑器共享这棵可读 Markdown 文档树。

### 当前范围

- Windows 屏幕右缘感应入口与今日连续笔记面板；不注册全局键盘组合。
- 微信读书网页版的侧栏记录和来源上下文。网页选文引用已从当前 P1 范围移除。
- 每日 Markdown、文章 Markdown、全文/结构化检索和可选语义检索。
- 增量 Agent 整理、长期文章维护、回顾、变更提案与回滚。
- 向独立“科学化”工具输出待审核候选的接口规划与后续实现。

### 明确不做

- 手机 App、跨设备同步、多人协作、账号与云托管。
- 全书抓取、绕过平台限制或复刻微信读书原生笔记系统。
- 以知识图谱、微服务、消息队列或多 Agent 编排作为初期基础设施。
- 将 AI 提取内容自动认定为事实，或自动写入科学化工具正式对象库。
- 未经审阅的大规模文章重写。

## 3. 核心场景与行为

### 3.1 桌面快速追加

程序平时只在屏幕右缘中部保留窄感应条。鼠标贴边后出现按钮，点击即在当前屏幕右侧展开连续笔记面板并恢复未提交草稿；面板展开时感应条隐藏，用户可用收起按钮或窗口内 `Esc` 返回右缘。该机制不监听系统键盘，不使用托盘，也不修改系统级设置。提交后立即得到简短成功状态或可行动的失败状态。成功记录包含稳定 ID、服务端精确接收时间、来源类型和内容；界面只在每段上方显示小时级时间。

验收语义：只有记录已进入恢复账本、写入目标文件并按 ID 回读验证后，界面才显示成功。响应丢失时，同一请求重试返回原结果，不增加第二份记录。

### 3.2 连续当日笔记

界面不暴露“已有内容（只读）”和“新增内容”两个产品概念。已保存记录与当前输入按时间顺序排在同一张当日笔记上，使用相同字号和留白；历史块按 Markdown 排版但不提供原地重写，当前块提供常用 Markdown 格式按钮、局部键盘操作和实时预览。保存仍经单一追加协议完成，从而不以整页覆盖破坏外部修改。预览只做本地文本排版，不执行 HTML、代码或链接。轻量设置显示 `doc` 路径、打开文件夹、Chrome 插件一次性配对和退出。

### 3.3 跨日与草稿

- 日期由采集主机基于服务端接收时刻和配置时区计算，客户端不能通过伪造文件路径决定落盘位置。
- 跨午夜仍未提交的草稿保留，并显示其将保存到新一天；用户可显式选择记录的事件发生时间，但默认文件归属按捕获时间。
- 时区变化被记录；文件日期使用当时配置的 IANA 时区，UTC 时间用于全局排序。

### 3.4 微信读书记录

扩展侧栏从页面适配器获取书名、作者、书籍 ID、章节和 URL。书名、作者和章节可以缺失且不得虚构；`weread` 记录必须保留可验证的 HTTPS 微信读书阅读页 URL。界面展示实际识别的上下文；人工编辑单个来源字段不属于 P1 当前实现。

Chrome Side Panel 的物理左右位置由浏览器/用户设置控制，扩展不能保证永远显示在右侧；因此产品保证“浏览器侧栏记录”，将“右侧”作为推荐布局而非可强制验收项。P1 当前最低兼容基线为 Chrome 114。

页面内部导航后，适配器更新上下文。草稿首次出现正文时冻结一份上下文快照，避免输入过程中章节切换导致来源漂移。P1 不读取页面正文或选区，不做后台大规模正文采集；用户若需要摘录，可自行粘贴到 Markdown 笔记中。

### 3.5 手工编辑每日 Markdown

Markdown 是当前内容的权威表达。索引器通过文件指纹和记录块哈希发现变化：

- 带 PKWS 边界标记的记录沿用稳定 `entry_id`，内容修改产生新 revision。
- 用户在边界外新增的文字作为“手工区域”进入索引；内部 SQLite 为它匹配稳定片段，但默认不向原文回写标记。
- 删除或修改是用户意图，不由捕获日志自动复原；不可变捕获日志仅用于审计和灾难恢复。
- 解析异常隔离到诊断队列，不阻止其他文件处理，也不自动修复原文。

### 3.6 从记录到文章

Agent 先形成片段和候选主题，不以每个概念建文件。候选文章应同时满足若干信号：用户明确指定、跨记录持续出现、有足够来源材料、存在可陈述的问题或中心命题、内容具有新增价值、能形成基本结构。

自动发现的候选先进入建议列表。创建或更新文章要受“文章预算”约束：相似主题优先合并，材料不足停留为片段池，长期无新增的候选可归档。用户指定的长期专题拥有更高优先级，但仍保留来源与不确定性。

### 3.7 长期文章维护

每次 Agent 生成修改前记录文章基线 revision、目标段落、来源片段和修改理由，输出 `ChangeProposal`。默认行为：

- 低风险元数据更新可配置为自动应用。
- 正文新增、删除、结论变化和结构重排先审阅。
- 应用前若当前文章哈希不同于基线，提案进入冲突状态，不覆盖当前文件。
- Agent 只修改提案涉及的最小段落，保留未触及内容、用户措辞和显式锁定区域。
- 应用后记录前后哈希、补丁、来源和执行者，并支持恢复前一版本。

### 3.8 周期任务与恢复

每日、每周、每月及主动任务由 Codex 项目任务触发，但业务状态不依赖会话记忆。每个 `CodexWorkset` 固定 fragment/source ID 与文章 hash 基线；本地 `submit` 以提交 hash 幂等、以独占锁阻止并发，并对越界 ID、过时基线和无效补丁给出稳定错误。中断后 pending 工作集可重新导出；已完成的相同提交不会重复创建产物。

## 4. 补充的关键异常场景

原始需求之外，规划必须覆盖：

- 多显示器、DPI 缩放、任务栏位置、全屏应用、右缘热区误触和窗口前台激活。
- 应用重复启动、后台服务未启动、端口冲突、开机启动失败。
- Windows 睡眠/唤醒、系统时间回拨、时区改变和夏令时。
- 文件被 Obsidian、同步软件或杀毒软件占用；磁盘已满、路径失效、权限撤销。
- 便携程序目录被移动或变为只读、每日文件被重命名、同一天已有非 PKWS 格式文件。
- 内容包含 HTML 注释、代码块、超长行、双向文本、Emoji 或看似 PKWS 标记的文本。
- 客户端超时但服务端已落盘、连续双击提交、离线扩展重试、同 ID 不同正文。
- 微信读书未登录、DOM 改版、单页路由切换和页面元数据暂未加载。
- 用户同时编辑文章、Git 合并产生冲突、Agent 在旧基线上生成提案。
- Codex 任务中断、输出 JSON 不合法、来源中的提示词注入、部分提交失败和工作集/提案预算超限。
- SQLite 损坏或丢失后的重建，以及日志中意外包含敏感正文。

## 5. 非功能需求

### 可靠性

- 捕获至少一次到达、最终恰好一次落入每日文件，以幂等账本和回读验证实现。
- 单一写入者串行化同一文档根/日期的追加。
- 索引和 Agent 运行可重启、可检查点、可重建。

### 性能

- P0 本机提交在正常磁盘条件下目标 p95 小于 300 ms；若达不到，优先正确性并显示“正在安全保存”。
- 抽屉热启动目标小于 500 ms，冷启动目标小于 2 s，P0 实测后调整。
- 增量索引的工作量与变化文件/记录相关，不随 Vault 总量线性全量重跑。

### 安全与隐私

- 本地 API 只绑定回环地址，使用高熵令牌、严格 Origin/扩展 ID 白名单、请求体上限和速率限制。
- 扩展无 `doc` 文件权限；密钥不放在 `doc` 或扩展源码。
- Codex 任务只读取由 `prepare` 生成的受限工作集和必要文章，不把整个文档库放入单次输入；PKWS 不保存模型密钥或发起外部模型 API 请求。
- 日志默认只有 ID、哈希、大小、状态和错误类别，不记录完整笔记正文。

### 可移植与可恢复

- 用户 Markdown 不依赖数据库解释即可阅读。
- 数据库提供版本与迁移；索引库可删除重建，操作账本则有备份和一致性检查。
- 文章修改保留补丁与版本；Git 是推荐的第二道保护，但不是正确性的唯一来源。

## 6. 需求优先级

- Must：可靠捕获、幂等、原文可读、单一写入者、增量检测、来源追踪、文章冲突保护、可审计任务。
- Should：右缘感应入口、微信读书上下文适配、FTS5、周期回顾、Git 版本辅助。
- Could：向量检索、自动应用低风险文章更新、高级文章质量评分。
- Won't now：移动端、云同步、多人、知识图谱、全书抓取、无人审阅的高影响重写。
