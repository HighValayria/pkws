# P1 Chrome 插件：安装、使用与人工验收

## 当前状态

P1 v0.1.2 已实现到可由 Chrome 开发者模式加载的阶段，构建产物位于 `apps/browser-extension/dist`。自动化测试使用脱敏 HTML fixture 和系统临时文档目录；真实微信读书页面仍需完成剩余人工验收，因此当前状态是“实现完成，待人工验收”，不是正式发布。网页选文引用已按用户决定从本阶段撤下。

## 从零开始使用

### 1. 构建桌面端和插件

要求 Windows 10/11、.NET 10 SDK，以及 Node.js 24（开发构建）。在仓库根目录运行：

```powershell
Set-Location F:\Projects\notes
.\scripts\test.ps1

Set-Location .\apps\browser-extension
npm install
npm run check
npm test
npm run build
```

`npm run build` 会重建 `apps/browser-extension/dist`。最终使用插件不需要保持 Node.js 进程运行。

### 2. 启动 PKWS 桌面端

开发运行：

```powershell
Set-Location F:\Projects\notes
.\scripts\dev.ps1 -Show
```

也可在退出正在运行的旧实例后执行 `scripts/publish.ps1`，再运行便携发布目录中的 `PKWS.exe`。本次开发期间现有发布文件被运行中的 PKWS 锁定，未强制结束进程，因此必须先重新发布才能在便携版中看到配对区域。桌面端运行时，本地 API 只监听 `127.0.0.1:27123`。

### 3. 在 Chrome 加载插件

1. 打开 `chrome://extensions/`。
2. 开启右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择 `F:\Projects\notes\apps\browser-extension\dist`。
5. 建议把“PKWS · 微信读书笔记”固定到浏览器工具栏。

当前最低 Chrome 版本为 114。侧栏实际显示在左侧还是右侧由 Chrome 的侧栏设置决定，插件不能强制。

### 4. 首次安全配对

1. 展开 PKWS 桌面笔记，点击右上角设置图标。
2. 在“Chrome 插件”区域点击“生成配对码”。
3. 点击 Chrome 工具栏中的 PKWS 图标打开侧栏。
4. 打开侧栏右上角连接设置，输入 6 位配对码。

配对码只能使用一次，5 分钟后失效，连续输错 5 次会作废。插件获得的是与自身扩展 ID 和 Origin 绑定的独立随机凭证，不会读取桌面主令牌。长期凭证只存于 `chrome.storage.local`；桌面端只保存其哈希。再次配对同一扩展会使旧凭证失效。

### 5. 记录

- 在 `https://weread.qq.com/web/reader/...` 阅读页点击扩展图标，侧栏会显示已识别的书名、作者、章节和来源链接。
- “当前来源”卡片可点击标题栏收起；收起后只保留单行书名，折叠状态保存在浏览器本地。
- 直接在“我的笔记”中输入 Markdown，点击“保存到今天”。
- 草稿首次有文字时冻结来源。之后切书、切章或切标签页不会静默替换草稿来源；可按原来源保存，也可显式“改绑到当前页”。改绑会生成新的 `request_id`。草稿按标签页保存，并按来源保留一个重启恢复副本。
- 保存超时后插件先按同一 `request_id` 查询状态。无法确认时不清空草稿；再次保存仍使用同一 ID，依靠 P0 幂等账本避免重复。

最终每日 Markdown 位于 `<PKWS.exe 所在目录>\doc\Daily\YYYY\YYYY-MM-DD.md`，微信读书记录以普通 Markdown 显示来源和“我的笔记”，同时保留隐藏记录 ID 与结构化来源账本。当前插件不读取网页选区；需要摘录时可直接粘贴到 Markdown 输入区。

## 权限与数据边界

插件仅申请：

- `sidePanel`：显示浏览器侧栏；
- `storage`：保存草稿和配对凭证；
- `tabs`：识别当前活动标签页；
- `https://weread.qq.com/*`：运行来源适配器；
- `http://127.0.0.1:27123/*`：由扩展后台调用本地捕获 API。

插件不申请文件系统、Cookie、浏览历史、右键菜单、动态脚本执行、全站或代理权限，不读取微信登录 Cookie，不修改 Windows 代理、注册表、系统快捷键或开机启动。Content Script 不持有本地 API 凭证，也不能让网页指定任意请求地址或文件路径。

## 适配器策略与已知降级

适配器版本为 `weread-dom-v1`。稳定标识优先取阅读页 URL；可见书名、作者和章节使用一组集中管理的选择器并允许缺失。Content Script 以节流的 `MutationObserver`、URL 轮询和导航事件识别 SPA 变化，不扫描或抓取整本书。

自动化测试包含两种脱敏 DOM 结构、字段缺失和非支持页面。真实页面选择器与切章时序仍需人工验证。若 DOM 失效，侧栏会显示书名或章节暂未识别；只要仍是可识别的阅读 URL，来源 URL 和用户笔记不应被伪造。完全不支持的页面会禁用新草稿绑定。网页选文引用因真实页面上无法稳定取得选区，已从 v0.1.2 移除，不属于本清单。

## 人工验收清单

以下均尚未由自动化测试替代，执行时请使用用户认可的非敏感测试内容：

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| T01 | 加载 `dist` | 扩展无清单或 Service Worker 错误 |
| T02 | 打开阅读页并点击图标 | Side Panel 打开并识别支持页面 |
| T03 | 核对来源 | 书名、作者、章节、ID、URL 与页面一致；缺失字段不虚构 |
| T04 | 切书/切章/切标签 | 当前来源更新，非空草稿仍绑定原来源并显示提示 |
| T05 | 关闭再开侧栏 | 当前标签页草稿和稳定请求 ID 恢复 |
| T06 | 自由输入 Markdown | 多段文本完整保存，Markdown 可读 |
| T07 | 快速双击保存 | 按钮保存期间禁用，不产生两条记录 |
| T08 | 停止桌面端后保存 | 不虚报成功、不清空草稿 |
| T09 | 服务恢复后重试 | 使用同一请求 ID，成功且不重复 |
| T10 | 保存响应超时 | 显示不确定状态，草稿保留，可安全重试 |
| T11 | 重启 Chrome/后台 | 草稿恢复行为可接受；配对凭证仍有效 |
| T12 | 未授权网页请求 localhost | 无凭证或错误 Origin 无法写入 |
| T13 | 桌面端继续记录 | 桌面和插件仍写入同一日期文件 |
| T14 | Obsidian/文本编辑器查看 | Markdown、小时、来源链接、中文和 Emoji 可读 |
| T15 | 收起“当前来源”后重开侧栏 | 只显示单行书名；展开后章节、作者和链接完整恢复 |

如扩展源码更新，重新执行 `npm run build`，然后在 `chrome://extensions/` 点击该扩展的“重新加载”。
